# OpenStack Heat — advanced templates (task 1–10)

Each template takes `external_net`, `image` and `flavor` parameters
(defaults match the course cloud), so it can be pointed at any OpenStack:

```bash
openstack stack create -t task4.yml --parameter trusted_cidr=203.0.113.0/24 task4
openstack stack output show task4 --all
```

| Task | Topic | Heat features used |
|---|---|---|
| 1 | Router + one internal network, per-VM security groups | `OS::Neutron::Router`, `RouterInterface` |
| 2 | One router joining two internal networks | multiple subnets, SG rules by CIDR |
| 3 | Two networks, services limited to a trusted network | parameterised `remote_ip_prefix`, any-protocol rules |
| 4 | Linux VM as router/NAT, RFC 1918-only services, SMB | fixed-IP ports, `port_security_enabled`, `OS::Heat::Value` |
| 5 | VMs on the external network, TLS mail, intra-group traffic | `remote_mode: remote_group_id` |
| 6 | Jump host, Apache app server, Squid proxy | fixed IPs, `user_data` provisioning |
| 7 | SSH key pair generated by the template | `OS::Nova::KeyPair`, `save_private_key` |
| 8 | Name derived from the stack, IP as output | `OS::stack_name`, `outputs` |
| 9 | Optional Telnet rule | `conditions`, `OS::Neutron::SecurityGroupRule` |
| 10 | N identical VMs | `OS::Heat::ResourceGroup`, `%index%` |

## Task 1 (`task1.yml`)

Router with one internal network (`192.168.88.0/24`) and two VMs. PC1 allows
ICMP + DNS, PC2 allows ICMP + HTTP/HTTPS.

```
Internet (ext-net-154)
        |
    [Router]
        |
  [192.168.88.0/24]
     /        \
  [PC1]      [PC2]
 ICMP+DNS   ICMP+HTTP/S
```

## Task 2 (`task2.yml`)

One router connecting two internal networks: PC1 in `192.168.33.0/24`, PC2 in
`192.168.35.0/24`. ICMP and FTP on both, HTTP/HTTPS only on PC2, traffic
allowed between the networks.

```
Internet (ext-net-154)
        |
    [Router]
     /      \
[net-33]   [net-35]
192.168.33.0/24   192.168.35.0/24
   |                   |
 [PC1]               [PC2]
ICMP+FTP         ICMP+FTP+HTTP/S
```

## Task 3 (`task3.yml`)

One router, two networks: network A (`10.0.1.0/24`) with PC1 and network B
(`172.16.99.0/24`) with PC2 and PC3. ICMP, SSH and RDP everywhere;
HTTP/HTTPS and DNS only from `trusted_cidr` (default: the university network
`158.193.0.0/16`); all traffic allowed between the internal networks.

```
Internet (ext-net-154)
        |
    [Router]
     /         \
[10.0.1.0/24]  [172.16.99.0/24]
    |               /      \
  [PC1]          [PC2]    [PC3]
        all: ICMP, SSH, RDP
        HTTP/S + DNS: only from trusted_cidr
```

## Task 4 (`task4.yml`)

A dual-homed Debian router VM with IP forwarding and NAT in front of
`10.255.55.0/24` with PC1 and PC2. SSH and RDP only from `trusted_cidr`,
HTTP/HTTPS and DNS only from RFC 1918 ranges, and PC2 additionally allows SMB.

The router VM's internal port has a fixed address (`10.255.55.254`) and
port security disabled so Neutron does not drop forwarded packets; the
subnet has no Neutron gateway, and the PCs set their default route to the
router VM in `user_data`.

```
Internet (ext-net-154)
        |
  [Router-VM]  <-- dual-homed (ext + int), NAT/ip_forward
        |  10.255.55.254
  [10.255.55.0/24]
     /              \
  [PC1]           [PC2]
  ICMP             ICMP
  SSH+RDP (trusted)     SSH+RDP (trusted)
  HTTP/S+DNS (RFC1918)  HTTP/S+DNS (RFC1918)
                        + SMB (445, 139, 137-138)
```

## Task 5 (`task5.yml`)

Two VMs attached directly to the external network (no router, no internal
network). ICMP and encrypted mail (SMTPS 465, submission 587, IMAPS 993,
POP3S 995) on both, SSH only on PC1, RDP only on PC2, and unrestricted
traffic between the two via `remote_group_id`.

```
Internet (ext-net-154)
     /          \
  [PC1]        [PC2]
  SSH           RDP
  ICMP, TLS mail (465, 587, 993, 995)
  <---- all traffic between the PCs ---->
```

## Task 6 (`task6.yml`)

Jump server (dual-homed), Neutron router with internal network
`10.0.0.0/24`, an Apache application server (fixed IP `10.0.0.25`) and a
Squid proxy (fixed IP `10.0.0.10`), both provisioned via `user_data`.

- SSH to the jump server only from `admin_cidr`; the app and proxy servers
  accept SSH only from the internal network.
- Squid accepts clients from `10.0.0.0/24` only (a drop-in under
  `/etc/squid/conf.d/`), and the security group limits port 3128 to the same
  range, so it is not an open proxy.
- The router omits `enable_snat`: setting it explicitly needs admin rights
  and fails with `403 Forbidden` for a regular project user.

```
         Internet (ext-net-154)
          /              \
  [Router]             [Jump-VM]
  ext gateway          ext + internal NIC
  10.0.0.1/24
       |                    |
       +----[10.0.0.0/24]---+
               /        \
    [App:10.0.0.25]  [Proxy:10.0.0.10]
       Apache2              Squid
```

## Task 7 (`task7.yml`)

VM on the external network with an SSH key pair generated by the template
(`OS::Nova::KeyPair` with `save_private_key: true`). The private key is
returned as a stack output.

Server-side key generation was removed in Nova API microversion 2.92, so
this works only where Heat still talks to Nova below that version.

```
Internet (ext-net-154)
        |
      [VM]  <-- key: <stack-name>-key

Outputs:
  private_key --> PEM key for SSH access
  vm_ip       --> address of the VM
```

## Task 8 (`task8.yml`)

VM on the external network named after the stack (`<stack-name>-server`).
Its IPv4 address is returned as an output.

```
Internet (ext-net-154)
        |
  [<stack-name>-server]

Outputs:
  vm_ipv4_address --> assigned IP address
```

## Task 9 (`task9.yml`)

VM with a security group that always allows SSH (TCP 22). Telnet (TCP 23) is
added only when `allow_telnet=true` (default `false`), using a Heat
`condition` on a separate `OS::Neutron::SecurityGroupRule` resource.

```
Internet (ext-net-154)
        |
  [server-task9]
        |
   [sg-task9]
    TCP 22 (always)
    TCP 23 (only if allow_telnet=true)
```

## Task 10 (`task10.yml`)

A user-chosen number of VMs (`vm_count`, default 2, max 5) from one
definition using `OS::Heat::ResourceGroup`. Each VM gets a unique name,
`<stack-name>-server-0`, `-1`, and so on.

```
Internet (ext-net-154)
    |    |    |   ...
  [VM-0][VM-1][VM-2]  (up to 5 VMs)
  <stack>-server-%index%

Outputs:
  server_ips --> IP address of each VM
  server_ids --> Nova IDs of the VMs
```
